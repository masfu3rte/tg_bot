# Telegram-бот @someout_bot

Исправленная версия на основе `8ff8d78`: проверка доступа и переходов сделки, точные денежные расчёты, устойчивая очередь уведомлений и сохранение форм. Репозиторий не содержит рабочего токена, базы пользователей, приватных ключей или авторизации Google Drive.

Требуется Python 3.12 или новее. Прямые зависимости зафиксированы в `requirements.txt`.

## Локальный запуск

```sh
python3 -m venv venv
venv/bin/python -m pip install -r requirements.txt
```

Создайте файл настроек из примера и ограничьте доступ к нему. Если `.env` уже существует, сохраните текущие настройки.

```sh
test -e .env || (umask 077; cp .env.example .env)
chmod 600 .env
```

Перед запуском заполните:

- `BOT_TOKEN`: токен отдельного тестового бота. Не запускайте вторую polling-копию с рабочим токеном одновременно с сервером.
- `MODERATION_CHAT_ID`, `REQUESTS_PUBLIC_CHANNEL_ID`: реальные ID тестовой группы и канала; при необходимости ID тем и баннеров.
- `MODERATOR_IDS`: ID сотрудников через запятую. При пустом значении модераторские действия доступны только администраторам рабочей группы. Даже сотрудник из списка должен использовать рабочую группу, а не личный чат.
- `MANAGER_REQUISITES_TEXT`, `MANAGER_CDEK_CONTACT_TEXT`: проверьте все данные перед использованием. В примере сохранены тексты из исходного проекта; их банковская и контактная актуальность не подтверждалась.
- `SUPPORT_USERNAME` и `SUPPORT_URL`: контакт поддержки. `REQUESTS_CHANNEL_URL` и `ADS_URL` необязательны; соответствующие кнопки скрываются, пока ссылки не заполнены.

Многострочный текст должен целиком находиться внутри одних кавычек. В примере используются строки с `\n` внутри двойных кавычек. Ошибки синтаксиса `.env` теперь останавливают запуск с номерами строк; значения не игнорируются молча.

```sh
venv/bin/python check_config.py
venv/bin/python main.py
```

`check_config.py` не подключается к Telegram и не изменяет базу. Он проверяет заполненность, а не действительность токена, банковских данных или прав в Telegram.

## Изменённое поведение

- Действия модерации проверяют чат и полномочия сотрудника; действия пользователя — владельца и сторону сделки.
- Заявки создаются после принятия условий. Нельзя откликаться на свою, неодобренную или уже занятую заявку.
- Подтверждённую оплату нельзя вернуть в ожидание обычной кнопкой. Начисление рефералу защищено отдельной уникальной записью в той же транзакции, что и финальная оплата.
- Запрос проверки платежа имеет версию. Старая модераторская кнопка не подтверждает новый запрос.
- Этапы доставки доступны после обоих залогов, назад этапы не переводятся. Завершённую сделку нельзя отменить кнопкой продавца.
- Активная сделка блокирует удаление и редактирование заявки. Завершённые записи доступны в архиве без действий отмены.
- Редактирование реализовано: личное название сохраняется сразу, название товара и описание отправляются на повторную модерацию. Устаревшие карточки модерации отклоняются.
- Цена хранится в копейках; все сообщения показывают копейки и используют один расчёт. Максимум — 100 000 000 рублей, срок — от 1 до 365 дней.
- Текстовые поля проверяют тип, непустое значение и длину. Пользовательские HTML-символы экранируются. Большой текст отправляется отдельно от фотографии.
- Выход в меню и `/cancel` завершают текущую форму. `/info` сохраняет её. Формы хранятся в отдельной SQLite-базе `FSM_PATH` и переживают перезапуск.
- Важные уведомления сохраняются в очереди `outbox` в основной базе. Временные ошибки повторяются с задержкой; после 10 попыток либо блокировки бота задание требует внимания сотрудника. Интерфейс сообщает об очереди вместо ложного успеха.

## Контроль доставки

В рабочей группе модератору доступны:

- `/delivery_status`: количество отправленных, ожидающих и заблокированных заданий.
- `/retry_delivery`: повтор ожидающих и заблокированных отправок после устранения причины.
- `/resolve_cancel ID_отклика`: закрыть спорную отмену **после ручной проверки платежей и завершения расчётов**. Команда сохраняет решение; банковских операций не выполняет. При запросе продавца об отмене после внесения залогов сделка сначала приостанавливается для проверки менеджером.

Нельзя гарантировать строго однократную доставку сообщения при обрыве связи после принятия сообщения Telegram: Telegram не предоставляет для этих вызовов общего ключа идемпотентности. Платёжные отметки и реферальные начисления при этом защищены независимо от сообщений. Предусмотрен запуск одного экземпляра polling-бота с одной базой.

Ручные отчёты: `/report_daily`, `/report_weekly`, `/report_monthly`, `/report_all`. Они доступны модераторам рабочей группы. Автоматические отчёты работают по UTC; ошибки записываются в журнал, попытка повторяется через минуту.

## Резервирование

Локальные снимки основной базы включены по умолчанию: `LOCAL_BACKUP_ENABLED=1`, интервал `LOCAL_BACKUP_INTERVAL_SECONDS=3600`. Используется SQLite Backup API и проверка целостности. Файлы `.sqlite.gz` сохраняются в каталоге `backups` рядом с базой; каталог имеет права `0700`, файлы — `0600`. Они не шифруются и содержат данные базы. Старые копии автоматически не удаляются: контролируйте свободное место и выбирайте срок хранения самостоятельно.

Снимки на том же диске помогают при ошибке приложения, но не защищают от потери сервера или диска. Для внешних зашифрованных копий настройте Google Drive/rclone и ключ age по [инструкции](docs/backups.md), затем включите `BACKUP_ENABLED=1`. Авторизация Drive и приватный ключ не входят в этот проект. Перед использованием проверяйте восстановление копии отдельно от рабочей базы.

Для локальной проверки восстановления `.sqlite.gz` распакуйте его в отдельный новый файл SQLite и выполните `PRAGMA integrity_check`. Не подменяйте работающую базу для проверки.

## Проверки

```sh
venv/bin/python -m unittest discover -s tests -v
```

Тесты используют отдельные базы и подменённую Telegram-сессию, сетевых запросов не выполняют. Дополнительные проверки охватывают полный путь сделки, доступ, повторную оплату, старые кнопки, редактор, длинный текст, сбои доставки, устойчивость состояния и миграции.

## Установка на сервер

Образец `deploy/tg_bot.service` использует отдельного пользователя `tg-bot`, закрытый каталог данных `/var/lib/tg-bot`, маску `0077` и ограничение записи. Перед установкой проверьте пути и параметры своего сервера.

Перед его установкой вручную создайте системного пользователя/группу, подготовьте Python-окружение и каталог настроек `/etc/tg-bot`. Файл `bot.env` должен читаться только владельцем процесса либо узкой группой `tg-bot`, например `root:tg-bot` с правами `0640`, а каталог — `0750`. Убедитесь в доступности токена и rclone-конфига именно пользователю службы.

Перенос базы требует отдельной процедуры: остановить единственный рабочий процесс, сохранить проверенную резервную копию, перенести базу с правильным владельцем и только затем запускать новую версию. Не запускайте локальную исправленную версию непосредственно на рабочей базе ради проверки миграции.
