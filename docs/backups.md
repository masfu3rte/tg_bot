# Резервные копии в Google Drive

Папка назначения:
https://drive.google.com/drive/folders/1vr5mU4Ph3dIUHB0vvlmwjqPpnoID0HtJ

Её ID закреплён в `config.py` (`BACKUP_DRIVE_FOLDER_ID`). Ссылки в `.env` не нужны.
Скрипт отправляет только зашифрованные файлы БД `.sqlite.gz.age`, а не `.env`, токены или ключи.

## Авторизация Google Drive

На сервере установите rclone из пакетов вашей системы, например для Ubuntu/Debian:

```bash
sudo apt update
sudo apt install rclone
```

От имени того же пользователя, который запускает бота, выполните:

```bash
rclone config
```

Создайте remote с именем `gdrive`, типом `drive` (Google Drive), выберите scope `drive`.
Авторизуйте Google-аккаунт, у которого есть право редактора в указанной папке.
Ссылка на папку сама по себе не даёт программе разрешение загружать файлы.
Если на сервере нет браузера, выберите вариант без браузера и следуйте инструкции rclone:
на своём компьютере с браузером и установленным rclone выполните `rclone authorize "drive"`,
затем перенесите результат в запрос авторизации rclone на сервере. OAuth-токен не публикуйте и не присылайте в чат.

Учётные данные rclone сохраняются в его локальном конфиге вне репозитория.
Если он расположен нестандартно, задайте путь через `RCLONE_CONFIG` в окружении или `.env`.
Не используйте сервисный аккаунт без проверки квоты и прав: для обычной личной папки здесь предусмотрен пользовательский OAuth.

## Ключ шифрования

На доверенном компьютере с копией проекта установите Python-зависимости и создайте ключ:

```bash
python -m pip install -r requirements.txt
python backups.py --generate-key someout-backup.agekey
```

Команда сохранит **приватный** ключ в `someout-backup.agekey` и выведет только публичный `BACKUP_AGE_RECIPIENT=age1…`.
Файл ключа сохраните вне сервера бота, например в менеджере паролей и на отдельном носителе.
Без него восстановить зашифрованные копии невозможно. Файлы `*.agekey` исключены из Git.
На сервер перенесите только публичный ключ, а не содержимое приватного файла.

## Настройки и первая проверка

В `.env` сервера добавьте:

```dotenv
BACKUP_ENABLED=1
BACKUP_RCLONE_REMOTE=gdrive
BACKUP_AGE_RECIPIENT=age1…
BACKUP_INTERVAL_SECONDS=3600
```

Вместо `age1…` вставьте настоящий публичный ключ, полученный на предыдущем шаге.
Путь БД берётся из существующей переменной `DB_PATH`. При отсутствии файла пустая БД не создаётся.
Если rclone не находится в PATH, дополнительно задайте `BACKUP_RCLONE_BINARY` с абсолютным путём к нему.

Из директории проекта, тем же Python и пользователем, что запускают бота:

```bash
python backups.py --check
python backups.py
```

Первая команда проверяет настройки и чтение папки, вторая создаёт и загружает реальную копию.
Снимок создаётся через SQLite Backup API, проверяется `PRAGMA integrity_check`, сжимается и шифруется age.
После загрузки проверяется MD5 зашифрованного файла, предоставляемый Google Drive.
Несовпадение контрольной суммы считается ошибкой. Временная локальная папка удаляется после завершения,
в том числе при ошибке загрузки. Постоянный локальный архив не создаётся; рабочая БД остаётся на сервере.

После успешной разовой загрузки перезапустите бота: включённые копии отправляются при старте и далее раз в час.
Операции с БД и сетью выполняются в отдельном потоке, не блокируя обработку сообщений.
Ошибка резервирования пишется в журнал, следующая попытка будет через заданный интервал.
Если бот остановлен, встроенное расписание тоже остановлено. Уведомления об ошибках в Telegram пока не реализованы.
Скрипт не удаляет старые копии из Drive: следите за свободным местом и удаляйте ненужные версии отдельно.

Для отдельного процесса, например под управлением systemd, есть команда:

```bash
python backups.py --loop
```

В этом случае задайте `BACKUP_ENABLED=0` для процесса бота, чтобы не запускать два расписания одновременно.
Команды разовой загрузки и `--loop` работают по явному вызову независимо от `BACKUP_ENABLED`.

## Проверка восстановления

На доверенном компьютере скачайте нужный `.sqlite.gz.age` из Drive и положите рядом приватный ключ.
В примере замените имя скачанного файла:

```python
import gzip
from pathlib import Path
import shutil
import sqlite3
import pyrage

identity = pyrage.x25519.Identity.from_str(Path("someout-backup.agekey").read_text().strip())
pyrage.decrypt_file("скачанный-файл.sqlite.gz.age", "restored.sqlite.gz", [identity])
with gzip.open("restored.sqlite.gz", "rb") as source, open("restored.sqlite", "xb") as target:
    shutil.copyfileobj(source, target)
with sqlite3.connect("restored.sqlite") as db:
    assert db.execute("PRAGMA integrity_check").fetchall() == [("ok",)]
print("Копия расшифрована, целостность SQLite подтверждена")
```

Проверьте нужные записи в восстановленной БД. Для возврата в работу остановите бота,
сохраните текущую БД на случай отката, замените её проверенной восстановленной копией и запустите бота.
При остановке должны закрыться все подключения SQLite; не оставляйте рядом старые файлы WAL/SHM от другой версии базы.
Проверяйте восстановление периодически, а не только после аварии.
